摘要

ControlScope 提出一种评估与改进 LLM 智能体工作流修订能力的框架，系统对比三种修订方式：继续生成代码、编辑工具调用参数、替换未完成工作流；并区分‘可用修复’与智能体‘实际选择动作’，以揭示可靠性瓶颈。

核心观点与创新点

  • 1首次形式化定义 LLM 智能体在执行中态下的工作流修订空间
  • 2构建三类可操作修订动作（续写/编辑/替换）的统一评估协议
  • 3实证发现智能体常忽略更优修复选项，暴露决策不可靠性
  • 4提出基于修订意图识别与动作合理性校准的可靠性诊断方法
  • 5开源 ControlScope 基准与分析工具链，支持细粒度修订行为追踪

主要方法

要解决的问题
LLM 智能体在执行中断或错误后缺乏可控、可靠的工作流修订能力
整体思路
通过构造可控执行中断场景，观测智能体在相同状态下的多路径修订行为，并解耦‘修复可能性’与‘动作选择偏好’
关键设计
  • 定义执行中态（in-execution state）作为修订触发锚点
  • 枚举并标准化三类原子修订动作及其语义约束
  • 引入‘修订可行性标注’与‘动作选择日志’双轨记录机制
  • 设计修订成功率、意图一致性、冗余动作率等可靠性指标
实验设置
基于 ToolBench 和 WebShop 等多任务基准构造中断注入场景；测试 GPT-4、Claude-3、Qwen-Agent 等主流智能体

结论与影响

论文结论
智能体修订行为高度依赖提示工程而非内在可靠性机制；可用修复与实际选择间存在显著偏差；参数编辑动作被严重低估。
对领域的影响
为 LLM 智能体可靠性研究提供首个聚焦‘工作流动态修订’的基准与分析范式，推动从静态响应转向过程可控性评估。
局限
当前实验限于单步中断场景；未覆盖跨工具依赖与长程状态回溯修订
