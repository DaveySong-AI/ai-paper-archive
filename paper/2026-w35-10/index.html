GUI-CC 基准：评测 GUI 世界模型作为 Agent 环境的上下文一致性

GUI-CC： Benchmarking Contextual Consistency of GUI World Models as Agent Environments

时间
2026-08-30 08:00（6 天前）
阅读原文arXiv:2609.00048来源页

本节内容由 AI 自动生成，未经人工审核，可能存在偏差，仅供参考。

摘要

Infer-forge 是一套面向 SGLang 推理优化的内部工程系统，提出 MonoRepo、Harness、Task Loop 与 Task Graph 四种结构化机制，将模型、SLO、硬件拓扑、运行时及加速平台等多维部署点约束，转化为可复现、可审计的端到端工程流程。

核心观点与创新点

  • 1提出‘部署点约束链’概念，强调推理优化有效性依赖全局部署上下文而非局部代码变更
  • 2引入 Harness 作为标准化测试与验证接口，统一评估不同配置下的性能与合规性
  • 3设计 Task Loop 结构支持迭代式调优闭环，实现配置-执行-反馈-修正的自动化循环
  • 4构建 Task Graph 表达跨组件依赖关系，显式建模模型、调度器、通信路径与硬件间的耦合
  • 5采用 MonoRepo 统一管理所有工程资产（模型、脚本、配置、指标），保障可复现性与可审计性

主要方法

要解决的问题
推理优化在局部代码层面看似独立，但其实际有效性高度依赖全局部署上下文（如模型特性、SLO要求、网络拓扑、运行时行为、加速平台能力）
整体思路
将部署点约束链工程化：通过四层抽象（MonoRepo→Harness→Loop→Graph）将隐式依赖显式建模为可组合、可追踪、可重放的系统流程
关键设计
  • Harness：定义标准化输入/输出契约与断言接口，封装模型加载、请求注入、指标采集与SLO校验
  • Task Loop：以配置驱动的闭环执行引擎，支持基于指标反馈的自动参数搜索与策略切换
  • Task Graph：DAG形式描述任务间数据流与约束依赖，支持跨层级（模型→调度→通信→内核）影响分析
  • MonoRepo：单一代码仓库集成全部配置模板、基准脚本、验证规则与历史快照，绑定Git commit与部署点元数据
实验设置
基于SGLang v0.3+框架，在LMSYS组织的多厂商GPU集群（A100/H100）上开展端到端推理服务验证；覆盖LLaMA-2/3、Qwen、Phi系列模型及vLLM/SGLang后端对比

结论与影响

论文结论
推理优化的有效性必须锚定于具体部署点；脱离约束链的孤立优化易导致线上失效，而结构化工程流程可显著提升优化迁移成功率与问题归因效率
对领域的影响
为大模型推理系统工程提供了可复现范式，推动从‘经验调参’向‘约束驱动开发’演进，对MLOps与AI Infra领域具方法论启示
局限
当前Task Graph依赖人工建模，自动化依赖图推断能力尚未集成；多租户隔离与动态SLO适配未在原文详述
